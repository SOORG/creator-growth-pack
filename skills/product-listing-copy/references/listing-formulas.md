# Digital listing formulas — illustrative examples only

Use these as prompts for structure. **Never state that example files or benefits are included unless the creator confirms them.**

## Titles

- {Primary use} for {buyer} — {verified format}
- {Verified count} {type of asset} for {task} — {niche}
- {Outcome supported by proof} — {product type}

## Description structure

1. A real user problem (based on the supplied audience description).
2. Actual product functionality and what it does **not** do.
3. Confirmed deliverables with filenames, format and count.
4. Supported software/platform versions and accessibility, if verified.
5. License/usage limitations and a clear non-misleading CTA.

## Category examples (not product inventory)

**Spreadsheet:** describe input workflow, supported formulas and summary fields, but only when documented. Never assert Excel/Sheets/Numbers compatibility without testing.

**Design templates:** describe editability, file formats, tool requirements and third-party asset licensing as verified by the creator.

**E-book:** describe actual chapters, page count and file formats; leave any unknown as `[VERIFY]`.

**Preset/assets:** describe tested versions, installation steps, previews and supported software, not hypothetical compatibility.

## Pricing approach

Use cost, support effort, legitimate comparables, target buyer, supported value and platform requirements. Report currency and the exact assumptions. The original source's USD price ladder is **not a verified pricing rule**; do not quote a fixed ladder without user-approved terms.
